# CLAUDE.md — публичный журнал I.C.S.Y. (`I.C.S.Y-predictions`)

Контекст для работы в этом репозитории. Полный контекст проекта — в репозитории кода `hoxitoo/I.C.S.Y-I-Can-See-You-` (основная ветка `claude/t-lite-publishing`): `CLAUDE.md` и `docs/status.md`, читать первыми.

## Что это

- Публичный журнал прогнозов CS2. Только дописывается. Прогноз попадает сюда до начала матча, результат — после.
- Код модели и публикации лежит в отдельном репозитории кода. Здесь только данные, README, workflow и лицензия.
- Сайт: https://hoxitoo.github.io/I.C.S.Y-predictions/. Telegram-канал: https://t.me/ICSYpublic, посты на английском.

## Кто что пишет

- **Данные пишет только бот GitHub Actions:**
  - `predictions/YYYY-MM-DD.jsonl`, `results/YYYY-MM-DD.jsonl` — день по UTC;
  - `telegram/posted.jsonl`.
  Руками их не правим и не коммитим: ни исправлений, ни «чисток». Ошибка данных исправляется только новой строкой по правилам формата.
- **Руками коммитятся только** `README.md`, `README.ru.md` (всегда вместе, EN и RU), `LICENSE`, `CLAUDE.md` и `.github/workflows/`.
- **Правила коммита:**
  - время в UTC (`TZ=UTC`), иначе в коммите виден часовой пояс автора;
  - почта автора — служебная `248290172+hoxitoo@users.noreply.github.com`;
  - в конце сообщения — строка `Co-Authored-By`.
- Перед коммитом — `git pull --rebase`: бот коммитит каждый час.

## Формат

- **Формат журнала v1.0** с 23.10.2026. Правила и поля — в README, разделы «Journal rules», «Record format», «Format versions» (в README.ru.md — «Правила журнала», «Формат записей», «Версии формата»).
- **Изменения формата:** 1.x — только добавления; 2.0 — изменение правил оценки, с объявлением в README заранее. Любое изменение — строкой в таблице версий и только после «да» владельца.
- **Скрипт «Check it yourself» / «Проверьте сами»** в README должен давать те же числа, что код (`journal.scored_series`). Меняешь правила оценки — проверь скрипт на текущем журнале.

## Workflow

| Файл | Когда | Что делает |
|---|---|---|
| `publish.yml` | Каждый час в :17, по внешнему триггеру (Cloudflare Worker, `workflow_dispatch`); `schedule` — запасной; также при пуше самого файла | Собирает VRS и Liquipedia, прогнозирует, сверяет результаты, коммитит журнал, постит в Telegram |
| `site.yml` | После успешных Publish и FACEIT | Собирает сайт RU/EN и выкладывает на GitHub Pages |
| `faceit.yml` | Каждые 6 часов | Форма игроков на FACEIT для сайта. Хранится в кэше Actions, не в журнале |

- Код берётся из репозитория кода: секрет `ICSY_CODE_TOKEN`, ветка — переменная `ICSY_CODE_REF` (по умолчанию `claude/t-lite-publishing`).
- **Секреты и переменные:**
  - секреты: `ICSY_CODE_TOKEN`, `FACEIT_API_KEY`, `TELEGRAM_BOT_TOKEN`;
  - переменные: `TELEGRAM_CHAT_ID`, `TELEGRAM_LANG` (= `en`).
  Значения добавляет только владелец.
- Версии actions — на Node 24. `astral-sh/setup-uv` закреплён точным тегом: мажорных тегов у него больше нет.
- Статус запусков и аннотации читаются через API без входа: `https://api.github.com/repos/hoxitoo/I.C.S.Y-predictions/actions/runs`. Логи шагов видны только после входа в GitHub.

## Чего здесь никогда нет

- Сырых данных источников. В журнале только прогнозы, результаты и ссылки на источники в `attribution`.
- Данных пробы PandaScore Historical и всего, что из них посчитано: по условиям PandaScore они только для внутреннего моделирования.
- Данных из демок HLTV.
- Секретов и токенов.
